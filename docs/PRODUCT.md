# 麦门星球 · 像素麦当劳点单助理
> 1024 超能 Coding 周末 · 用餐赛道 × 麦当劳程序员创意开发大赛 双赛作品
> 形式：H5 网页游戏（手机竖版）+ 麦当劳 MCP 真实点单

---

## 1. 一句话定位

**在一家像素风麦当劳里，跟 AI 店员聊两句，它帮你点好最合适的那一单——下单是真的，取餐号是真的，小游戏里的备菜进度也是真的。**

- 前半段是「实用」：AI 问答式点餐决策（几个人 / 减脂还是放纵 / 尝新还是下午茶 → 一套有依据的套餐组合，真实价格、真实热量）
- 后半段是「好玩」：像素风麦当劳门店，员工小人实时备菜，出餐后递给你一张**真实取餐号码牌**，你在真实门店凭它取餐，回游戏里评价打分，形成闭环

---

## 2. 对原方案的评估（哪些保留、哪些砍）

原方案方向是对的，「有人真的用过 + 真实闭环」恰好是两个加分点。但截止时间是 **10/25 23:59**，必须做减法：

| 原方案要素 | 判定 | 理由 |
|---|---|---|
| 开场 AI 问答（人数/目标/口味） | ✅ 保留，是核心 | 直接命中「实用」，且实现成本低 |
| AI 给套餐建议 | ✅ 保留，升级 | 必须用 **MCP 返回的真实菜单/价格/热量** 做依据，不能凭空编 |
| 游戏大厅（厨房/餐桌/员工） | ⚠️ 砍规模 | 只做一个「柜台+后厨」单屏场景，不做大厅多房间 |
| 员工小人实时备菜 | ✅ 保留，是记忆点 | 用状态机动画（接单→煎制→装配→出餐），映射订单状态 |
| 递号码牌（对应真实取号） | ✅ 保留，**全案最高光** | 「游戏里的号码=真实门店的号」这一刻最容易被评委记住 |
| 就餐进度可视化 | ⚠️ 简化 | 订单状态推进 + 倒计时即可，不做进食动画长流程 |
| 用餐结束评价 | ✅ 保留 | 评价落到评价墙，形成数据闭环，也方便演示"有人用过" |

**最大的合规与体验风险：真实下单涉及真实门店与支付。** 处理原则见 §6 风险兜底。

## 3. 与赛题评分标准的对齐

评委四条标准 → 本案对应：

1. **真的调用了麦当劳 MCP** → 三处硬调用：①拉真实菜单（价格/热量/新品/活动）②AI 推荐的每个单品都来自 MCP 菜单数据 ③**MCP 真实下单**，取真实取餐号。代码里用 `MCP_INTEGRATION.md` 逐一标注调用点。
2. **能跑通** → 主链路 3 分钟内可完整走完：问答→推荐→下单→号码牌→进度→评价。
3. **实用或好玩至少占一样** → 两个都占：省钱/减脂点餐建议是实用；像素门店备菜是好玩。
4. **有人真的用过加分** → 用 WorkBuddy「应用发布」把 H5 一键发布成公开链接，直接发到麦门社群/朋友圈收集真实使用，评价墙晒真实数据。

## 4. 用户流程（竖版单手操作）

```
[开屏] 麦门星球 logo（像素 golden arches）
   │
[① 对话] AI 店员「小麦」问答（3~4 轮，点选项即可，不用打字）
   · 几个人吃？
   · 今天的目标：减脂 / 放纵大吃 / 尝新品 / 下午茶小食 / 带娃
   · 有没有忌口 & 预算上限（可选）
   │
[② 推荐] AI 给出 1 套主推 + 2 个备选，每个方案展示：
   · 单品清单 + **真实单价**（来自 MCP 菜单）
   · 总价 / 总热量 / 人均
   · 推荐依据一句话（"2 人减脂：主推板烧鸡腿堡+零度可乐，比巨无霸省 340 kcal"）
   用户点「就这个」→
   │
[③ 下单] 调 MCP 真实下单（见 §6 支付处理）
   · 成功 → 拿到真实订单号/取餐号
   │
[④ 门店] 切入像素门店场景（竖屏单屏）：
   · 你坐在柜台前（像素小人）
   · 3 个员工小人状态机：接单（接过你的小票）→ 后厨备菜（煎炉冒烟/薯条出锅，进度映射订单状态或预估时间）→ 出餐
   · 出餐瞬间：员工递上一张**号码牌特写**，牌上印真实取餐号 + 门店名
   · 文案："凭这张号去 XXX 路门店取餐，游戏里会同步你的等餐进度"
   │
[⑤ 等餐/进度] 游戏内进度条：制作中 → 请取餐 → 用餐中（用户手动点"我取到餐了"）
   │
[⑥ 评价] 星级 + 一句话标签（快/香/划算/出餐慢…）→ 写入评价墙
   · 评价墙展示所有真实用户评价（证明"有人用过"）
```

## 5. 技术架构与实现形式

**选型：H5 单页（手机竖版 375×812 逻辑分辨率）+ Node 轻后端代理 + mcd-mcp 连接器，用 WorkBuddy 开发并一键发布公开链接。**

```
手机浏览器
   │  H5（原生 JS + Canvas 2D 像素场景）
   ▼
Node Server（WorkBuddy sites deploy 沙箱，单端口）
   │  /api/menu  /api/recommend  /api/order  /api/order/:id  /api/reviews
   ▼
WorkBuddy mcd-mcp 连接器 → 麦当劳 MCP
   · 查菜单（价格/热量/新品）
   · 查门店
   · 创建订单 / 查订单状态
```

### 关键实现点

1. **像素风不用美术资源**：CSS `image-rendering: pixelated` + Canvas 逐格绘制；员工小人 4 帧走路/3 帧备菜动画，调色板只用麦当劳红黄白+深棕，8~12 个 sprite 手绘编码即可，工作量可控。
2. **AI 推荐逻辑**：服务端用 MCP 菜单数据做规则化组合（预算约束 + 热量约束 + 忌口硬过滤），文案由 LLM 润色；**推荐理由必须引用真实数字**（价格/热量差），这是"选择有依据"的硬要求。
3. **备菜进度**：MCP 若提供订单状态查询则轮询映射；若不提供，按品类预估时间推进（汉堡 4 min / 小食 2 min），并在 UI 标注"游戏内预估进度"，不冒充真实状态。
4. **评价墙**：服务端内存/文件存储即可，公开链接下所有人共享同一面墙。

## 6. 风险与兜底（截止前必须想清楚）

| 风险 | 兜底方案 |
|---|---|
| MCP Token 来不及批/门店覆盖不到 | 服务端做 `MCP_MODE=live|demo` 开关，demo 模式回放缓存的 MCP 真实响应；**但演示录屏必须用 live 模式真实下单一次** |
| 真实下单要支付 | 优先走 MCP 支持的"下单待支付/小额支付"路径；演示用最低价单品（如 1 个圆筒）真实走通全链路，把支付截图/录屏放进 MCP_INTEGRATION.md。产品内默认下单不自动扣款，支付动作始终由用户确认 |
| 游戏做不完 | 游戏场景降级为「号码牌转场动画 + 进度条」，问答+推荐+真下单链路保住评分基本盘 |
| 没人用过 | 发布公开链接后，今晚先发 3~5 个朋友实测，评价墙有初始数据 |
